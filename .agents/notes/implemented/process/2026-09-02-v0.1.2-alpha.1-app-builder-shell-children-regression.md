# Agent Note: Phase 1.5 post-merge fix-up #2 — app-builder-shell boot regression and transient overlay

Status: implemented

English

A companion to the [Phase 1.5.7 post-merge fix-up #1](2026-09-02-v0.1.2-alpha.1-seed-manifest-fix.md) and the [App Builder shell re-skin design note](2026-08-30-app-builder-shell-on-upstream-web.md). Fix-up #1 closed the build-time seed-map drift. Fix-up #2 closes the structural children-table regression that surfaced immediately after, in the very same browser boot.

## Problem

After `7d62a7c557` lands, `pnpm dsh web` boots the page, hydrates the React tree, and renders the classic UI root error screen:

```
Failed to load plugins
@deepseek-ai/dsh-client-ui-app-builder-shell
failed to apply loader entry 94a8edc6 (@deepseek-ai/dsh-client-ui-app-builder-shell):
slot "app-builder-shell" is not declared
(a parent entry's children table must declare it)
```

The browser console carries one and only one error: that single thrown `Error` from the slot registry. No network failures, no other loader entries refuse to apply, no "Failed to load plugins" toast from any other plugin. The page renders an error card and zero interactive buttons.

### Why the design says it should work

The shell plugin's `apply` body, in `packages/client/ui-app-builder-shell/src/client/index.ts:128`, calls

```ts
ctx.slots.inject('root', () => ctx.slots.register({
  name: 'app-builder-shell',
  locale: NS,
  children: {
    'app-builder.projects':     { kind: 'single', scope: 'root' },
    'app-builder.preview':      { kind: 'single', scope: 'root' },
    'app-builder.conversation': { kind: 'single', scope: 'session' },
  },
  store: storeHandle,
}, Shell))
```

The chain take-over pattern: the shell waits for `root` to be declared, then registers itself as an alternate renderer of root. `packages/client/ui-app-builder-shell/src/client/contract/slots.ts:20` declares the slot spec statically (kind: `single`, scope: `root`, owner: `AppBuilderShellOwnerProps`). The shell bundle therefore declares the slot it sits in.

The runtime disagrees. `packages/client/ui-slots/src/index.ts:785-788` looks up `this.records.get(options.name).spec` at every `register` call:

```ts
register(options: ErasedOptions, component: unknown): () => void {
  const rec = this.records.get(options.name)
  if (!rec?.spec) {
    throw new Error(`slot "${NAME}" is not declared (a parent entry's children table must declare it)`)
  }
  ...
}
```

`this.records` is populated exclusively by parent entries' `register` calls — each parent's `children: { ... }` object populates the child slot records with their spec. `packages/client/ui-layout/src/client/index.ts:123-141` is the only entry that registers `root`, and its `children` table is

```ts
children: {
  'sidebar':        { kind: 'single', scope: 'root' },
  'conversation':   { kind: 'single', scope: 'session-maybe' },
  'details':        { kind: 'single', scope: 'session' },
  'shell.overlay':  { kind: 'list',   scope: 'root' },
}
```

There is no `app-builder-shell` row. The `ctx.slots.inject('root', ...)` callback fires once `root` mounts, the shell's `register({ name: 'app-builder-shell', ... })` then runs, the registry looks up `app-builder-shell`, finds no `spec`, and throws.

### Why this regression only surfaces post-merge

The upstream v0.1.2-alpha.1 tree does not ship `packages/client/ui-app-builder-shell`; that package is Phase 1.5.3's [apps-web-reskin-on-upstream](2026-08-30-app-builder-shell-on-upstream-web.md) work. The merged tree added it on top of upstream's `apps/web` shell. The new package declares its own slot (`app-builder-shell`) in its `SlotMap` augmentation and tries to register into it, but no parent entry in the merged tree ever declared it. The chain take-over works in source design but breaks at apply time.

`grep -rn` against `packages/` for `app-builder-shell` children-declaration patterns confirms exactly one matching declaration: the static `SlotMap` augmentation in `packages/client/ui-app-builder-shell/src/client/contract/slots.ts:20`. The static `SlotMap` is a TypeScript convenience; the runtime record is created only when a parent's `register` call passes a matching `children` entry. The merged tree never adds that parent-level declaration.

This class of regression is invisible to the existing static gates. `verify-client-packages` validates npm dependency edges; `verify-cordis-config` validates loader cordis.yml rows; neither walks the slot parent/child graph that `apply()` calls establish. The merged tree passes every gate the merged tree adds and still cannot boot because one slot declaration lives only in source.

## Decision

Disable the three App Builder entries through a transient boot overlay (`pnpm dsh web --patch`), leaving the merged tree source untouched. The patch file lives at `C:\Users\<user>\AppData\Local\Temp\dsh-3081.patch.yml` and applies three `disabled: true` rows:

- `app-builder-shell` (the structural regression — no parent declares its slot)
- `app-builder-projects` (pre-existing: `!!js /__dsh/...` interpolation hits a JS-eval regex literal bug)
- `app-builder-snapshot-bridge` (pre-existing: `apply()` reaches `ctx.webServer` instead of `inject: ['webServer']`)

With the overlay, `pnpm dsh web` boots the classic UI (`sidebar | conversation | details`) cleanly. The shell never tries to apply, never throws, and the rest of the merged tree renders normally. The architectural fix is **not** in this hot-fix: adding the missing `app-builder-shell` row to `ui-layout` root `children`, plus restoring the two BFF bridges once their upstream bugs are fixed, is the per-area 1.5.x follow-up tracked below.

This continues the [Phase 1.5.7 fix-up #1](2026-09-02-v0.1.2-alpha.1-seed-manifest-fix.md) pattern: each merged-tree regression is patched through a transient boot overlay, with the architectural fix-up tracked separately. The pattern keeps the merged tree source pristine while unblocking the base web frontend; the per-area 1.5.x follow-up sub-phases own the source changes once their architectural decisions land.

### Why this decision, not the architectural fix

- **Adding `app-builder-shell` to `ui-layout` root children declaration** requires deciding chain vs single kind for the slot spec (the `SlotMap` says `single`; the comment at `packages/bundle/web-app/cordis.patch.yml:304-307` says "chain take-over"), updating `AppFrame` to honor a chain priority on the `root` slot, and re-running the full slot-graph coverage. The existing test lane (`pnpm run test:gui`) covers `ui-layout` only with `children` mock lists; a new `verify-bundled-slot-graph` gate would need to ship alongside the fix.
- **Dropping the three App Builder entries from `packages/bundle/web-app/cordis.patch.yml`** is a permanent removal, not a transient disable. That touches the bundled surface for every consumer of `@deepseek-ai/dsh-bundle-web-app`. Phase 1.5 / 1.5.3 already shipped the bundle wiring; reverting it in this hot-fix would force the next-phase re-skin to re-merge upstream `apps/web` shim work.
- **Fixing the upstream bugs in the two BFF bridges and the shell children-table** is correct but out of scope for the boot-overlay hot-fix; the goal here is to unblock the base web frontend.

The patch overlay is reversible: removing the three `disabled: true` rows restores the merged tree intended shape, and the architectural fix can land in its own PR. This is the same trade-off the [Phase 1.5.7 fix-up #1](2026-09-02-v0.1.2-alpha.1-seed-manifest-fix.md) made (manifest pin vs hot-fix refactor).

## Alternatives considered

### Why not add `app-builder-shell` to `ui-layout` children and fix it now?

The architectural fix is correct; the immediate question is whether to do it in this hot-fix or in a per-area follow-up. The merge landed 1,130 upstream commits plus 9 path B commits; the per-area 1.5.x sub-phases (1.5.7 catalog generators, 1.5.3 webworker-runtime corpus, 1.5.2 examples relocation, App Builder re-skin follow-ups) own the architectural work. Forcing the App Builder shell children-declaration decision into this hot-fix would either (a) pick `chain` vs `single` without the slot-system team input, or (b) defer the fix to a separate stack PR anyway. Either path costs more than the boot overlay: (a) risks a wrong default that the slot-system note (forthcoming) would then have to walk back, and (b) re-creates the boot-blocker while the stack PR is in flight. The overlay unblocks the base web frontend today; the architectural fix lands behind a single source-controlled decision. Rejected for this PR; tracked below.

### Why not drop the three App Builder entries from `cordis.patch.yml` outright?

A permanent removal would require coordinating with the next-phase App Builder follow-up (chunk 5 SSE, chunk 6 project events, 1.5.4 webworker runtime) so the next re-skin PR does not have to re-discover the wiring. The transient overlay keeps the source untouched; the next-phase re-skin PR owns the decision to either re-enable the entries or replace them. Rejected.

### Why not wrap the shell `inject` call in a try/catch and let it fail silently?

The shell `register` throws at apply time inside the `ctx.slots.inject` callback. Wrapping the callback in `try { ... } catch {}` would silence the error and the shell would never mount. The classic UI would still render (because `ui-layout` owns `root`) — but the failure mode would be invisible: a future developer would see the shell disabled and not know why. The current error card with a one-line cause is the canonical "fail loud" path; suppressing it is a debugging regression. Rejected.

### Why not disable the entry in the merged tree source?

`packages/bundle/web-app/cordis.patch.yml` is the source of record for the bundled surface. Disabling `app-builder-shell` there permanently changes the bundle for every consumer of `@deepseek-ai/dsh-bundle-web-app`. The Phase 1.5 brief says the App Builder re-skin is in flight; disabling the bundle row would force the next-phase follow-up to either re-add it (extra merge conflict) or work around a missing entry (extra design surface). The transient `--patch` overlay scopes the disable to one local `pnpm dsh web` invocation without touching the source. Rejected.

## Invariants

- The merged tree source remains pristine: no entry in `packages/bundle/web-app/cordis.patch.yml`, no `disabled: true` row in any package `cordis.yml`, no source-level disable. The boot overlay lives in `%TEMP%` and applies only to the current `pnpm dsh web` invocation.
- The classic UI (`sidebar | conversation | details`) is the boot surface until the per-area App Builder re-skin follow-up lands. The shell is non-essential for the base web frontend; the design comment at `packages/bundle/web-app/cordis.patch.yml:304-307` says the classic UI is the documented fallback.
- The shell `SlotMap` declaration in `packages/client/ui-app-builder-shell/src/client/contract/slots.ts:20` continues to declare the slot type contract (kind, scope, owner). The architectural fix is to add a matching `children` row in `packages/client/ui-layout/src/client/index.ts`; the runtime record will then be created at `ui-layout` apply time, and the shell `ctx.slots.inject('root', ...)` callback will resolve the spec before calling `register`.
- `verify-client-packages`, `verify-cordis-config`, and the other 9 pre-existing `pnpm run hygiene` failures stay failing as they were before this fix. None are introduced or relaxed by the overlay.
- Port 3080 (PID 10632, the GUI-side harness) is untouched. Port 3081 is the agent-started boot server for the overlay; both are documented in `CLAUDE.md` §11.

## Consequences

- The base web frontend boots in classic UI mode and renders the full shell (`DSH Local Build` sidebar, workspace tree, sessions list, composer, model selector, settings). All workspace CRUD operations, sessions, projections, and settings panes remain available — only the App Builder 3-pane shell (projects | chat | preview) is unavailable. Playwright diagnostic confirms 36 buttons rendered, zero console errors, zero "Failed to load plugins" toast.
- The architectural decision (chain vs single kind, AppFrame chain priority handling, `verify-bundled-slot-graph` gate) is owned by the per-area App Builder re-skin follow-up. Adding `app-builder-shell` to `ui-layout` children is the source change; the rest of the fix lands behind it.
- The two pre-existing BFF bridge bugs (`!!js` regex literal, `ctx.webServer` typo) remain in the merged tree source. They are still non-essential for the base web frontend; restoring them requires the upstream bugs to be fixed and the bridge tests to cover real composition.
- The merge follow-up thread now has two notes ([#1](2026-09-02-v0.1.2-alpha.1-seed-manifest-fix.md), this one) and one future gate (`verify-bundled-seed-map` plus, implicitly, a `verify-bundled-slot-graph`). Both gates are part of the per-area 1.5.x follow-up; until they ship, manual sanity checks after a `vite build` (seed-map grep, slot-graph grep) catch regressions early.
- The boot overlay (`C:\Users\<user>\AppData\Local\Temp\dsh-3081.patch.yml`) is transient: a fresh `pnpm dsh web --patch` invocation with a different (or absent) overlay reverts to the merged tree intended shape. The next agent that picks up the App Builder follow-up can either reuse the same overlay path or land the architectural fix and remove the disable.

## Risks

- **Overlay drift.** A future `pnpm dsh web` invocation without the `--patch` flag reverts to the broken state. The patch path is documented in the runtime log (`dsh web: opening the default browser; pass --no-open to disable`), but a fresh developer landing on this tree may not know to add the flag. The architectural fix is the durable resolution; the overlay is the boot blocker. Until the architectural fix lands, the recommended local-invocation recipe (`pnpm dsh web --patch C:\Users\<user>\AppData\Local\Temp\dsh-3081.patch.yml`) belongs in the merge handoff or the per-area follow-up branch.
- **Children-graph coverage gap.** `verify-client-packages` and `verify-cordis-config` together cover npm edges and loader rows; neither walks the runtime slot parent/child graph. The architectural fix should land alongside a `verify-bundled-slot-graph` gate (analogous to the planned `verify-bundled-seed-map`) so the next regression of this shape fails CI instead of the browser smoke. Until the gate ships, a manual grep for slot children-declaration patterns under `packages/` after every `packages/client/ui-layout` or `packages/client/ui-app-builder-shell` change catches regressions early.
- **Architectural decision unresolved.** The `SlotMap` declares the slot spec as `kind: 'single'`; the design comment in the bundle says "chain take-over". Until a maintainer picks one, the architectural fix in `ui-layout` cannot land — adding `app-builder-shell` as a `single` slot means the shell cannot replace the layout, only sit alongside it; adding it as a `chain` slot means `AppFrame` must honor chain priority. This decision blocks the per-area follow-up; it is not in scope for the boot-overlay hot-fix but should be the first agenda item when the slot-system team picks up the merge thread.
