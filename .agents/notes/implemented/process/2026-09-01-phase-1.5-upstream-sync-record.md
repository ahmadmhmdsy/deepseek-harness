# Agent Note: Phase 1.5 / 1.5.7 — Planning artifacts + 1.5.5 regression fixes + English-only documentation

Status: implemented

Branch: `docs/phase1.5-record` (stacked on `adopt/subagent-provider`).

Stack position: 1.5.7 (above 1.5.6, the terminal sub-phase of the Phase 1.5 stack).

## Problem

Sub-phase 1.5.5 (commit `8994998859 feat(api): adopt App Builder Host BFF cluster`) introduced the Typert Remote service in `packages/app-builder/api/` and the new `ctx.appBuilderProjects` / `ctx.appBuilderSnapshotBridge` Cordis services. Three side effects were not fixed in the 1.5.5 PR itself and were deferred to 1.5.7 per the `Phase 1.5 prompt.md` plan:

1. **Typert Remote boundary regression.** `packages/app-builder/api/src/index.ts:150` rejected the boundary with `Remote boundary contains non-JSON type unique symbol` because `ProjectId = string & { readonly __projectIdBrand: unique symbol }` leaked into 10 boundary field types (`GetProjectRequest.id`, `DeleteProjectRequest.id`, `DeleteProjectValue.id`, `StartSessionRequest.projectId`, `StartSessionValue.projectId`, `GetPreviewRequest.projectId`, `GetPreviewValue.projectId`, `DeployRequest.projectId`, `DeployValue.projectId`, `GetUsageRequest.projectId?`). The same file carried `unknown` in six payload positions (`GetTranscriptValue.header`, `GetTranscriptValue.records`, `ResumeSessionValue.header`, `SubscribeEventsFrame.header`, `SubscribeEventsFrame.records`, `SubscribeEventsFrame.event`) that the cordis-catalog verifier cannot type-link to a published source.

2. **JSDoc completeness on Cordis event declarations.** `project/created`, `project/deleted` (`packages/app-builder/project/src/index.ts`) and `app-builder-preview/dev-state` (`packages/app-builder/preview/src/index.ts` + `packages/app-builder/snapshot-bridge/src/index.ts`) shipped without the `@mode emit` + `@param` completeness that `verify-export-jsdoc` requires for event payloads, and without `@returns` on two service methods (`ProjectRegistry.has`, `ProjectRegistry.listSessionIds`). Same on `AppBuilderSnapshotBridgeAccessor.snapshot()`.

3. **Subsystem home missing for the two new services and two event scopes.** `gen-cordis-catalog.ts` `SERVICE_PAGE`, `EVENT_SCOPE_PAGE`, `SERVICE_WALK_EXEMPTIONS`, and `TYPE_LINK_EXEMPTIONS` all needed entries that the 1.5.5 PR did not include (the verifier rejects unknown service keys outright). `gen-doc-graphs.ts` `SERVICE_ROLES` similarly needed entries for the two new services, and `gen-config-catalog.ts` `findInject()` rejected the App Builder packages' `inject = [...] as const` pattern (the AST walker only inspected the direct array literal).

This sub-phase lands the planning artifacts (`docs/PROJECT.md`, `planning/{plan,goal}.md`, `planning/Phase 2 prompt.md`, `planning/inspect/{INDEX,SUMMARY}.md`) + every regression fix above, plus the new `docs/subsystems/app-builder.md` home page (English only — see "English-only documentation" below), and verifies that the `pnpm run doc-sync` gates introduced by 1.5.5 now pass for the in-scope set. The §9 backlog of pre-existing gate failures stays documented but unfixed.

## Decision

### 1. Boundary type fixes in `packages/app-builder/api/src/types.ts`

Replace 10× `ProjectId | string` with plain `string` in every Typert Remote boundary field (the `ProjectId` brand is a compile-time only assertion; runtime carriers still parse it back via `request.id as ProjectId` casts inside `projects.ts` / `preview.ts` / `sessions.ts`).

Add three imports for the upstream-owned types that the boundaries must reference:

- `SessionHeader` from `@deepseek-ai/dsh-session`
- `SessionHistoryRecord` from `@deepseek-ai/dsh-api-session-controller`
- `SessionWireEvent` from `@deepseek-ai/dsh-api-session-controller`

Replace the `unknown` positions with the proper types:

- `GetTranscriptValue.header: SessionHeader`, `records: readonly SessionHistoryRecord[]`
- `ResumeSessionValue.header: SessionHeader`
- `SubscribeEventsFrame.header?: SessionHeader`, `records?: readonly SessionHistoryRecord[]`, `event?: SessionWireEvent`

### 2. `packages/app-builder/api/src/sessions.ts`

Remove the now-unused `SessionHistoryRecord` import.

Rewrite `getTranscriptRemote` to derive `header` from `controller.inspect()` and `cursor` from `inspect().events.at(-1)?.seq ?? -1`, and to fetch the page via `controller.page()`. Combine them with `Promise.all([inspect, page])` so the read remains single-round-trip. `SessionPage` upstream only exposes `{ records, hasMore }`, so the previous `page.header` / `page.cursor` accessors no longer exist on the boundary side.

Tighten `resumeSessionRemote`'s cast for `inspect()` to `Promise<{ meta: SessionHeader }>`.

### 3. `packages/app-builder/api/src/events.ts`

Replace the previous `frame as Record<string, unknown>` cast with `frame as SessionFollowFrame` (a discriminated union of `{ type: 'snapshot', header, cursor, records, hasMore, projections }` and `SessionEventEntry` = `{ type: 'event', event: SessionWireEvent }`). Drop the previous `typed.event ?? typed` fallback: read `typed.header` / `typed.cursor` / `typed.records` / `typed.hasMore` for snapshots, and `typed.event.seq` + `typed.event` for events.

### 4. JSDoc completeness

- `packages/app-builder/project/src/index.ts` — add `@mode emit` + `@param event` + prose to the `project/created` and `project/deleted` event declarations; add `@returns` to `has(id)` and `listSessionIds(id)`.
- `packages/app-builder/preview/src/index.ts` — add `@mode emit` + `@param state` to the `app-builder-preview/dev-state` event declaration.
- `packages/app-builder/snapshot-bridge/src/index.ts` — same JSDoc enrichment on `app-builder-preview/dev-state`; add `@returns` to `AppBuilderSnapshotBridgeAccessor.snapshot()`.

## Alternatives considered

- **Keep `ProjectId` in the boundary and disable the `unique symbol` check.** Rejected: the check exists because `unique symbol` brands do not survive JSON serialization on the wire; relaxing it would hide a category of bugs rather than fix them. The runtime re-assertion in `projects.ts` / `preview.ts` / `sessions.ts` (via `request.id as ProjectId`) preserves the compile-time guarantee without leaking the brand across the boundary.
- **Wrap each unknown payload position in a generated Zod schema.** Rejected: the upstream `SessionHeader` / `SessionHistoryRecord` / `SessionWireEvent` types are already JSON-safe (their leaves are primitives + branded ids). Referencing the upstream types directly is the single source of truth.
- **Add an exemption table entry rather than fixing the JSDoc.** Rejected: the completeness invariant applies to every Cordis event declaration; weakening it for one set of events creates a debt that will surface in the next cordis-catalog regen.
- **Translate the ZH side of `capability-seams.{md,zh.md}` / `event-producer-consumer.{md,zh.md}` / `config-catalog.{md,zh.md}` to absorb the regenerated EN rows.** Rejected: an English-only documentation policy (this commit) is incompatible with continued ZH translation work. The structural divergence is now a legitimate §9 consequence of the new policy.
- **Drop the `docs/subsystems/app-builder.md` page.** Rejected: the page is required for the `SERVICE_PAGE` / `EVENT_SCOPE_PAGE` entries in `gen-cordis-catalog.ts` to resolve. Without the page the verifier rejects the service / event scope registration outright.
- **Continue iterating the ZH side in `gen-cordis-catalog.ts` and create a stub `app-builder.zh.md`.** Rejected: an English-only documentation policy forbids new `*.zh.md` files. The script now skips the ZH iteration entirely.
